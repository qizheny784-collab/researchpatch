# 任务协调策略进化

遵循 ResearchPatch 项目协议。读取实际变更单、执行轨迹、人工反馈、现有策略及预算。无需为每次成功任务强行提炼新技能。

## 候选策略

只有存在可复用模式、真实遗漏或明确的新项目要求时提出策略。保留反馈原文和事件 ID；不要要求 Agent 先故意失败，也不把预设演示轨迹当真实经历。

策略文件包含 policy_id、version、status(candidate/active/retired)、trigger、action、exceptions、scope、source_events、tests、approval、supersedes。把它存入项目 policies/；不直接修改全局技能或系统提示。

例如“当评价口径改变时，检查所有参与比较的方法是否同步重算”是条件策略；“所有改动都重新做综述”范围过大，不应晋级。

## 测试与晋级

至少设计一个应该触发的正例和一个不应触发的反例。比较旧策略与候选策略，保持任务、基础模型、工具、总预算及人类提供的信息一致。记录漏报、误报、过期结论使用、时间与人工分钟数；不以模型自评分代替验收。

先进行开发/回归检查，研究员接受且检查通过后可以在本项目 active。跨任务迁移主张必须另有冻结后未见任务测试。若新测试结果用于继续修改，该组已成为开发资料，不能再称最终盲测。

没有执行测试就保持 candidate，不能把示例答案写成测试结果。若无优势、引入误报或成本超出约束，保留旧策略，或在研究员确认后收窄适用域。记录失败和负结果。

## 输出

策略差异、真实来源、适用边界、正反例、实测结果或待测状态、人工接受记录及激活版本。分开说明“项目内容已更新”“回归测试通过”“未见任务迁移得到支持”，避免夸大 RSI。

验收：策略可撤回，有触发与例外，不修改评测答案或验收标准，不把一条项目结论泛化成跨项目事实。
