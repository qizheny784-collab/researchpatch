# 研究图可视化

读取当前项目真实的 current.json，必要时读取相关变更单和快照。遵循主智能体的状态与来源协议。优先使用配套的 render_graph.py；未提供时可以实现相同输入输出，不能虚构导出成功。

## 产物

- research-map.html：离线可打开，可点击节点查看状态、适用范围和来源；新状态需要重新导出。
- research-map.svg：当前状态的静态图，适合截图、文档与视频。
- current.json：原始结构化依据，保持独立可查。

运行示例，路径按实际环境调整：

```text
python render_graph.py --state <项目目录>/current.json --out <项目目录>/visualization
```

每次初始化、变更单生成、执行验证或人工确认后，重新导出。按阶段重导出不等于实时自动连接；未实现文件监听或推送时，不宣称实时同步。HTML 中的节点操作只查看信息，不批准变更、不执行实验、不伪造事件。

## 表达规则

1. 节点和边来自当前状态，保留稳定 ID。依赖关系与支持/反驳关系使用不同线型或标签；relation 仅说明关系，不自动给科学结论赋真值。
2. 用文字和颜色同时表达状态，保留 proposed、unknown、needs_check、needs_rerun、needs_narrowing、contradicted、withdrawn、superseded、valid 的差别。
3. 默认展示项目、版本、数据来源和未确认项。候选论断不得显示为人工确认，历史结果不自动显示为当前有效证据。
4. 支持条件组若存在，显示条件卡，标出 all/any；不把多前提支持简化为一条无条件支持边。
5. 只有真实的版本快照与事件才可用作历史回放。若使用人工案例或预设阶段，显著标为受控示例/演示，不模拟真实运行日志。
6. 使用适合录屏和阅读的字号，小图以 8–15 个节点为宜；大型图按相关子图导出并说明省略范围。

## 分享与验收

实际打开 HTML 检查节点点击、中文、边标签及文件路径；检查 SVG 和 JSON 状态一致。平台若不能预览 HTML，提供静态图与文件下载；PNG 只在确实完成转换后交付。分享链接应使用未登录或独立访问环境核对权限和产物是否可见。

最终说明哪些是实际状态、哪些是待确认建议，以及文件是静态导出还是已实现实时同步。不能用制作精美的图替代计算与协调效果证据。
