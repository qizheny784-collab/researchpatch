# 项目研究状态

遵循 ResearchPatch 主智能体的项目状态协议。若协议未提供，先索取该配置或明确输出临时草案，不自行假定平台有专用状态 API。

## 初始化

1. 读取研究目标、范围、实际资料和可用预算。仅询问确实影响执行的缺失信息。
2. 从文件提取对象并赋稳定 ID，如 L001、H001、D001、E001、R001、C001。原始论断的存在与成立分开记录；未核查的输入结论标 unknown/needs_check。
3. 建立来源 → 依赖对象的有类型关系。确定的代码依赖写明文件依据；语义关系保留推断标记，优先让研究员确认关键关系。
4. 为需要多个前提的论断建立 all/any 支持组；记录适用范围。对象变化不等于自动否定其全部后继。
5. 实际创建 current.json、events.jsonl 及需要的目录；生成当前版本快照。记录真实的来源路径和版本；没有执行结果就不要创建虚假结果文件。

## 恢复与读取

先读取项目状态、未完成变更单及当前策略版本，再加载相关源文件。检查路径是否可访问、文件内容是否改变。聊天记忆与项目文件冲突时，核对原始证据并显式记录冲突；不直接相信较新的自然语言总结。

只加载当前任务相关子图及必要前提，保留稳定 ID；不要每次把所有历史塞进上下文。向平台记忆保存项目入口时，说明是否实际保存成功。

## 输出

- 项目 ID、revision、研究目标和当前证据范围。
- 小型节点表与 Mermaid 图；表中区分事实、假设、历史结果和当前有效结论。
- 待核查关系、缺失资料与未完成变更。
- 实际文件路径；无法持久化时明确给出待保存内容。

验收：稳定 ID 无重复，边的端点存在，来源可定位，关键论断有支持说明，初始化没有把推测或未运行结果写成已验证事实。
